Claude Code (Anthropic's AI coding assistant) was used for:

- **Research**: the libraries needed to build the Station Builder and the 3D views. This is far beyond my own C# and .NET
  experience.
- **Deciphering**: the fields and parameters of mod scripts, and the API calls needed.
- **Documentation**, and **troubleshooting** the station configuration and builder.

No, the GUI and the messages are my brain's doing. Can't blame that one on the AI.

## The project's stance

Use of AI is fine, but you must understand, or at least have conceptual awareness of, what your code or reports mean,
and be able to verify the assumptions, i.e. "Trust But Verify". On this project the verifying happens in Transport
Fever 3 itself: nothing is marked as working in the Readme until it has been tried in the game, or, for the Toolbox's
own windows, used day to day.

- If you can't debug or follow what the AI has written, then you shouldn't submit or use it.
- Use common sense, if you generated art or assets be up front - and exercise judgement on what you ask models to create.

Don't like it? That's your choice. Don't attack contributors, members or users for it; any such comments or mail go
straight in the bin.

If you've spotted anything not disclosed here for any reason, open a constructive PR for it - Transparency helps everyone.
